# Database Schema

> Two sources. **Migrated**: `tenants`, `users`, `refresh_tokens`, `clients`,
> `projects`, `project_test_configurations` in [`apps/backend/prisma/schema.prisma`](../../apps/backend/prisma/schema.prisma).
> **Draft, not migrated**: every other table below, in
> [`apps/backend/prisma/drafts/domain.prisma`](../../apps/backend/prisma/drafts/domain.prisma),
> moved into the active schema by the phase that needs it. Domain columns come from the
> lab forms (FPC01-01, FPC06-01, FPC06-04) and the questionnaire answers of 2026-10-15
> ([../domain/analysis/](../domain/analysis/README.md)). Each column's doc comment in the
> Prisma file names the printed field or the answer it comes from.

## Conventions

| Convention | Rule |
|-----------|------|
| Primary keys | `uuid` generated by the app/DB. Never expose sequential IDs. Lab numbers (registro, muestra, espécimen, informe) are separate columns. |
| Lab numbers | Registro, muestra and espécimen numbers are **consecutive per project** (Q-55, Q-57, Q-58): integer columns with a `UNIQUE (project_id, …)` constraint. Samples and specimens carry a copy of `project_id` for that. Printed forms (`MCH-068`, report number) are formatted, not stored, except `reports.report_number` (frozen at issue). |
| Naming | Prisma models in PascalCase/camelCase, mapped to `snake_case` tables/columns. Column names carry the unit (`_cm`, `_mm`, `_m3`, `_kg_cm2`, `_kgf`, `_c`, `_pct`, `_g`, `_s`). |
| Tenancy | `tenant_id uuid not null` on every tenant-owned table. Composite FK to parents. See [relationships.md](relationships.md). |
| Domain dates | `DATE` (date-only), e.g. `field_records.pour_date`, `specimen_tests.test_date`. |
| Times of day | `TIME(0)` for clock times written on the forms (delivery times, molding time, test time). They belong to the date of their row. API format `HH:MM`. |
| Instants | `timestamptz` (UTC), e.g. `created_at`, `generated_at`. |
| Measurements | `numeric(p, s)` (Prisma `Decimal`), never float. The scale matches the precision written on the forms. |
| Equipment codes | Free text as written (e.g. `CCP-PRE-05`). No equipment catalog to start (Q-29). |
| Calculated values | **Not stored** (A-73): means, area, N, stress, MPa, %, rates, averages, unit weight, cumulative volume, sheet number, age tolerance. Formulas: `src/specimen-tests/domain/compression.ts`. Storing results for audit is development-plan 7.5. |
| Nullability | Domain columns are nullable so a `DRAFT` can be saved incomplete. Completeness is a service rule (Q-33). |
| Lifecycle | Native enums. Transitions only through domain methods ([lifecycle.md](../domain/lifecycle.md)). |
| Deletion | No hard deletes after `DRAFT`. Use `CANCELLED` status. Records are kept at least 4 years (Q-52). |
| Audit | Required by the accreditation (Q-54): `audit_events`, Phase 10.2. |
| JSON | Only `reports.snapshot`. Never for domain fields (ADR-003). |
| Indexes | `tenant_id` always leads composite indexes. |

## Example queries

Pending tests up to a date for one tenant (illustrative). The SQL filter uses the
unshifted date; the service then applies the Sunday/holiday shift in
`scheduledTestDate()`:

```sql
SELECT st.id, sp.specimen_number, st.age_days, fr.pour_date + st.age_days AS nominal_date
FROM specimen_tests st
JOIN specimens sp     ON sp.id = st.specimen_id     AND sp.tenant_id = st.tenant_id
JOIN samples sa       ON sa.id = sp.sample_id       AND sa.tenant_id = st.tenant_id
JOIN deliveries de    ON de.id = sa.delivery_id     AND de.tenant_id = st.tenant_id
JOIN field_records fr ON fr.id = de.field_record_id AND fr.tenant_id = st.tenant_id
WHERE st.tenant_id = $1
  AND st.status IN ('SCHEDULED', 'IN_PROGRESS')
  AND fr.pour_date + st.age_days <= $2
ORDER BY nominal_date;
```

At A-50 scale (20–40 pours a month) this needs no stored `scheduled_date`.
