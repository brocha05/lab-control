# Preliminary Database Schema

> **DRAFT.** Source: [`apps/backend/prisma/schema.prisma`](../../apps/backend/prisma/schema.prisma)
> (validated with `prisma validate`, **no migration created yet**). It defines
> identity, ownership, tenancy, relationships, and lifecycle. Domain content columns
> are deliberately absent and marked `TBD`.

## Conventions

| Convention | Rule |
|-----------|------|
| Primary keys | `uuid` generated by the app/DB. Never expose sequential IDs. |
| Naming | Prisma models in PascalCase/camelCase, mapped to `snake_case` tables/columns. |
| Tenancy | `tenant_id uuid not null` on every tenant-owned table. Composite FK to parents. See [relationships.md](relationships.md). |
| Domain dates | `DATE` (date-only), e.g. `field_records.record_date`. |
| Instants | `timestamptz` (UTC), e.g. `created_at`, `performed_at`. |
| Lifecycle | Native enums. Transitions only through domain methods ([lifecycle.md](../domain/lifecycle.md)). |
| Deletion | No hard deletes after `DRAFT`. Use `CANCELLED` status (A-24). |
| JSON | Only `reports.snapshot`. Never for unknown domain fields (ADR-003). |
| Indexes | `tenant_id` always leads composite indexes. |

## Example queries

Pending tests up to a date for one tenant (illustrative):

```sql
SELECT st.id, st.age_days, fr.record_date + st.age_days AS scheduled_date
FROM specimen_tests st
JOIN specimens sp   ON sp.id = st.specimen_id AND sp.tenant_id = st.tenant_id
JOIN samples sa     ON sa.id = sp.sample_id   AND sa.tenant_id = st.tenant_id
JOIN field_records fr ON fr.id = sa.field_record_id AND fr.tenant_id = st.tenant_id
WHERE st.tenant_id = $1
  AND st.status IN ('SCHEDULED', 'IN_PROGRESS')
  AND fr.record_date + st.age_days <= $2
ORDER BY scheduled_date;
```

At A-50 scale this needs no stored `scheduled_date`. Measure before denormalizing.
